Connections (signal only; all buttons/buzzer/RTC share GND, display COM + RTC to 5V):

| Arduino pin | Device pin |
|---|---|
| 2–5 | 7-seg DIG1–DIG4 |
| 6–12 | 7-seg A–G |
| 13 | 7-seg CLN (colon, active-LOW: `digitalWrite(COLON_PIN, value ? LOW : HIGH)`) |
| A0 / A1 / A2 | Hours / Minutes / Alarm buttons (INPUT_PULLUP, press = LOW) |
| A3 | buzzer (`tone()`/`noTone()`) |
| A4 / A5 | DS1307 SDA / SCL |

**Display answer:** raw multiplexed **common-anode 4-digit 7-seg with colon**
(`wokwi-7segment`, NOT TM1637 / MAX7219 / LCD). Driven **via the SevSeg library**,
not raw GPIO: `sevseg.begin(COMMON_ANODE, 4, {2,3,4,5}, {6..12}, ...)`,
per-loop `sevseg.refreshDisplay()`, `sevseg.setNumber(hhmm)`,
`sevseg.setChars(" on"/" off"/"****")`, `setBrightness(90)`. Only the colon is
bit-banged directly (pin 13, `setColon()`).

## 4. `alarm-clock.ino` (194 lines, MIT © 2020 Uri Shaked)

Includes: `<SevSeg.h>`, `"Button.h"`, `"AlarmTone.h"`, `"Clock.h"`, `"config.h"`.
State machine `DisplayState { DisplayClock, DisplayAlarmStatus, DisplayAlarmTime, DisplayAlarmActive, DisplaySnooze }`
dispatched from `loop()` after `sevseg.refreshDisplay()`:

- `clockState` — shows time; Hour/Minute buttons `incrementHour/Minute`;
  short Alarm press toggles alarm → `DisplayAlarmStatus`; if `clock.alarmActive()` and
  Alarm released → `DisplayAlarmActive`.
- `alarmStatusState` — `setChars(" on"/" off")` for `ALARM_STATUS_DISPLAY_TIME` (1 s),
  then alarm-time view or clock.
- `alarmTimeState` — `setNumber(hhmm, -1)` for `ALARM_HOUR_DISPLAY_TIME` (2.5 s);
  Hour/Minute adjust alarm (resetting the timeout); Alarm press exits.
- `alarmState` — `alarmTone.play()` while Alarm held down; on release:
  long-press (`repeat_count() > 0`, 1 s repeat config) → `stopAlarm()` → clock;
  short-press → `snooze()` (9 min) → `DisplaySnooze` (`"****"` for 0.5 s).
- `setup()` — 115200 baud, `clock.begin()`, buttons `begin()` + `set_repeat`
  (Hour/Minute 500/200 ms auto-repeat; Alarm 1000/−1), `alarmTone.begin(A3)`,
  colon pin output, `sevseg.begin(...)` as above.

## 5. `config.h` (48 lines)

`USE_RTC 1`; `DISPLAY_TYPE COMMON_ANODE`; `ALARM_STATUS_DISPLAY_TIME 1000`,
`ALARM_HOUR_DISPLAY_TIME 2500`, `SNOOZE_DISPLAY_TIME 500` (ms);
`SNOOZE_TIME 9` (min); `DEFAULT_ALARM_HOUR 9`.

## 6. `Clock.h` / `Clock.cpp` (~50 + ~137 lines)

`Clock` wraps `RTC_DS1307 _rtc` (`USE_RTC=1`) or `RTC_Millis _rtc` (`USE_RTC=0`).
Alarm states `ALARM_DISABLED/OFF/ACTIVE/SNOOZED/STOPPED`; due-time = hour+minute
match; `alarmTime()` rolls to next day if past. Alarm enable/hour/minute persist
in DS1307 NVRAM bytes 0–2 (`readnvram`/`writenvram`; live version `#if USE_RTC`-guarded).
Time set = `adjust()` after `incrementHour/Minute` (minute increment wraps within the hour).

## 7. `Button.h` / `Button.cpp` (~40 + ~126 lines, MIT)

Debounced `INPUT_PULLUP` button: `read/pressed/released/toggled/has_changed`,
100 ms default debounce, `set_repeat(delay, interval)` auto-repeat with
`repeat_count()` (used for the Alarm long-press). `PRESSED = LOW`.

## 8. `AlarmTone.h` / `AlarmTone.cpp` (~18 + ~37 lines)

Non-blocking two-tone siren: `play()` calls `tone(pin, TONES[i], 500)` every
600 ms alternating 500/800 Hz; `stop()` calls `noTone()`. Melody = edit `TONES[]`.

## 9. README (76 lines) — hardware BOM + pin table

Uno R3, common-anode 4-digit 7-seg, 8× 220 Ω on segments, 4× PNP + 4× 4.7 kΩ
(optional), 3× pushbuttons, piezo, DS1307 (optional). Pin table matches §3.
Notes: common-cathode works by flipping `DISPLAY_TYPE` (and NPNs); 74HC595 /
TM1637 / HT16K33 / MAX7219 would save pins but need different code.

## 10. Porting assessment — running this on the noesis-lab bench

Local counterpart: `src/features/learn/gallery.ts` (`ALARM_CLOCK`,
"Alarm Clock with RTC") — a multi-file sketch doing the same job with
**raw GPIO multiplexing + raw `Wire` I2C** (no libraries), colon blink,
`digitalWrite` buzzer. Wiring follows the pin table exactly: DIG1–DIG4
(device pins 14/11/10/6) on D2–D5, A–G (13/9/4/2/1/12/5) on D6–D12, colon
CLN (pin 8) on D13 with COM (pin 7) to 5V, buttons on A0/A1/A2, buzzer on
A3, RTC on A4/A5. Gaps, easiest first:

1. **Multi-file: supported.** `FirmwareProject` holds up to 8 files
   (`src/features/simulation/firmware/project.ts:10`) and
   `FirmwareRuntime.fromProject` topologically merges local `#include "..."`
   with cycle detection (`src/features/simulation/firmware/interpreter.ts:505+`).
   **But:** entry must be named `main.ino` and every name must match
   `^[a-z0-9_-]+\.(ino|cpp|h|py)$` (`project.ts:12-28`) — Wokwi's
   `alarm-clock.ino` / `AlarmTone.h` / `Button.h` / `Clock.h` / `config.h` all need
   renaming (e.g. `main.ino`, `alarmtone.h`, …).
2. **Libraries: the blocker.** `#include` lines are inert to the parser
   (`src/features/simulation/firmware/parser.ts:390`), and the interpreter
   implements Arduino core + `Wire`/`SPI`/`Serial` only — `SevSeg`, `RTC_DS1307`,
   `DateTime`, `TimeSpan` have **zero** hits in the firmware engine. Options:
   (a) vendor minimal `SevSeg`/`RTClib` shims as extra project files mapping onto
   raw GPIO + `Wire` (moderate work; `DateTime`/`TimeSpan` arithmetic is the bulk);
   or (b) keep the port at the local gallery's level (raw multiplex + raw BCD `Wire`,
   as `gallery.ts:57-203` already does).
3. **Parts: ready.** DS1307 exists with register-level I2C including
   NVRAM `0x08–0x1F` as plain storage (`src/features/parts/devices/ds1307.ts:51-56`);
   3× `Tactile Button` + `Piezo Buzzer` exist (`src/features/parts/catalogue.ts:343`).
   The bench 4-digit 7-seg exposes all 14 KW4-56NALB pins (`D1–D4, A–G, DP`,
   `COM`+`CLN`); the colon is a COM/CLN diode driven active-low from D13,
   and `tone()`/`noTone()` have **no** firmware implementation, so `AlarmTone`
   is rewritten to `digitalWrite` beeps.
4. **Wiring reuse:** buttons A0/A1/A2, buzzer A3 (=17), digit commons D2–D5,
   segments A–G on D6–D12, colon on D13 all match urish's table one to one —
   no re-routing needed for a faithful port.

**Bottom line:** the bench can host a faithful *behavioral* port today (multi-file
works after renames), but a line-for-line port needs either `SevSeg`+`RTClib`
shims or a rewrite of display/RTC/tone to the raw primitives the local gallery
sketch already demonstrates.
