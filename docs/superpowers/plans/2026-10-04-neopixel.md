# NeoPixel Family Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a live single NeoPixel through a new `pixels` firmware port plus stateless matrix and ring parts with correct selection boxes.

**Architecture:** New `neopixel`, `neopixel-matrix`, `led-ring` component kinds in one focused sim file; a `PixelsPort` on the optional-service pattern with per-part LED buffers owned by the engine; colors painted through the existing `FootprintState` plumbing; Wokwi artwork wired through `WOKWI_PARTS`.

**Tech Stack:** TypeScript, Vitest, existing solver (no stamps needed — all pins are high-Z or supply topology), `@wokwi/elements` artwork.

**Spec:** `docs/superpowers/specs/2026-10-04-neopixel-design.md`

## Global Constraints

- Pin sizes in millimetres; element `pinInfo` px convert at 25.4/96.
- LED channels are integers 0-255; out-of-range values clamp, out-of-range indexes are ignored.
- The WS2812 waveform is not modeled in v1; record the limit in code.
- Matrix/ring colors are stateless artwork in v1; only the single gets live colors.

## Review Focus

- `pixels.setColor` with an out-of-range LED index is ignored instead of throwing.
- Channel values outside 0-255 clamp and round instead of wrapping or producing NaN.
- `pixels.*` on a pin with nothing wired is a no-op returning 0/false.
- Two NeoPixels hold independent buffers per part id.
- A matrix with floating DIN still solves to finite voltages (topology-only pins).

Matrix (8x8 default): `GND` x 22.83, `VCC` x 25.37, `DIN` x 27.91, `DOUT` x 30.45, y 48.05; size from the element's render math (width `5.66*8 + 1*7 = 52.28`, height to the pin row, verified against source at implementation time — do not trust the library's 25x25). Ring (16 pixels): 4-pin row from `pinXY` in source; size from the radius formula at 16 pixels, likewise verified. `GND`/`VSS` pins carry `net: 'GND'`.

Netlist: join the existing topology-only group (`case 'mcu': case 'breadboard': ... return []` in `netlist.ts`) — DIN is high-Z, supplies are topology, nothing is stamped.

### Task 2: `pixels` firmware port with live single

**Files:**
- Modify: `src/sim/firmware/interpreter.ts` (`PixelsPort` + dispatch + handler)
- Modify: `src/sim/engine.ts` (per-part LED buffers + pump-free accessor)
- Modify: `src/ui/simulation.ts` (`pixels` services + lookup mirroring `dhtOnPin` on `DIN`)
- Modify: `src/ui/footprints.tsx` (`FootprintState.pixels`), `src/App.tsx` (renderState), `src/ui/wokwi.ts` (`pushWokwiState` single `r/g/b`)
- Test: `src/sim/firmware/pixels.test.ts` (create); extend `src/sim/pixels.test.ts` with buffer tests

**Interfaces:**
- Consumes: `PixelColor`, `clampChannel`, `pixelCount` from Task 1; member-call dispatch beside the `dht.*` branch; `dhtOnPin` lookup shape; `state.steppers` plumbing shape.
- Produces: `PixelsPort { count(pin): number; setColor(pin, index, r, g, b): void }` (optional on `FirmwareServices`); `engine.pixelColors(partId): ReadonlyArray<PixelColor>`; `simulation.pixelColors(): ReadonlyMap<string, ReadonlyArray<PixelColor>>`.

Engine buffers: `Map<partId, PixelColor[]>` sized by `pixelCount` at `rebuildBus()` time (fresh arrays like servos — colors reset on topology change, mirror the precedent and note it); `setPixel(partId, index, color)` ignores out-of-range indexes; colors stored clamped. No pump needed (nothing is volts-derived); no re-solve needed (no circuit effect — settle after set like `servo.write`).

Interpreter: `if (callee.target.name === 'pixels') return this.evaluatePixelsCall(...)` after the dht branch. Handler (sync): `count` returns `services.pixels?.count(pin) ?? 0`; `setColor` calls `services.pixels?.setColor(pin, index, r, g, b)` and returns 0; default 0. Simulation services: `pixels: { count: (pin) => this.pixelsOnPin(pin)?.length ?? 0, setColor: (pin, i, r, g, b) => { const part = this.pixelsOnPin(pin); if (!part) return; this.engine.setPixel(part.id, i, { r, g, b }); this.engine.settle(); } }` with `pixelsOnPin` mirroring `dhtOnPin` on each kind's `DIN` pin (`neopixel`, `neopixel-matrix`, `led-ring`).

`pushWokwiState`: `if (kind === 'neopixel') { const c = state.pixels?.get(part.id)?.[0]; set(element, 'r', c?.r ?? 0); set(element, 'g', c?.g ?? 0); set(element, 'b', c?.b ?? 0); return; }` — matrix/ring fall through (stateless).

```ts
import { FirmwareRunner, type FirmwareServices } from './interpreter';

function stubServices(pixels?: { count: (pin: number) => number; setColor: (pin: number, i: number, r: number, g: number, b: number) => void }): FirmwareServices {
  return {
    nowMs: () => 0,
    pinMode: () => {},
    digitalWrite: () => {},
    digitalRead: () => 0,
    analogWrite: () => {},
    analogRead: () => 0,
    serialBegin: () => {},
    serialWrite: () => {},
    wire: { begin: () => {}, beginTransmission: () => {}, write: () => 1, endTransmission: () => 0, requestFrom: () => 0, read: () => -1, available: () => 0 },
    spi: { begin: () => {}, transfer: () => 0, end: () => 0 },
    ...(pixels ? { pixels } : {}),
  };
}

describe('pixels firmware', () => {
  it('sets a color through the port', () => {
    const calls: number[][] = [];
    const services = stubServices({
      count: () => 1,
      setColor: (pin, i, r, g, b) => calls.push([pin, i, r, g, b]),
    });
    const runner = new FirmwareRunner(
      'void setup() { pixels.setColor(2, 0, 255, 128, 0); } void loop() { delay(1000); }',
      services,
    );
    let guard = 0;
    while (runner.step() !== null && guard++ < 100_000) {}
    expect(calls).toEqual([[2, 0, 255, 128, 0]]);
  });

  it('is a no-op with no pixels service', () => {
    const runner = new FirmwareRunner(
      'void setup() { pixels.setColor(2, 0, 255, 0, 0); Serial.println(pixels.count(2)); } void loop() { delay(1000); }',
      stubServices(),
    );
    let guard = 0;
    while (runner.step() !== null && guard++ < 100_000) {}
  });
});
```
