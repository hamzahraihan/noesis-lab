# DHT22 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a DHT22 temperature/humidity part readable through a new `dht` firmware port.

**Architecture:** New `dht` component kind in a focused sim file; a `DhtPort` on the optional-service pattern with an `evaluateDhtCall` member-call handler beside the servo handler; SDA idle pull-up in the netlist; Wokwi artwork wired through `WOKWI_PARTS`.

**Tech Stack:** TypeScript, Vitest, existing solver stamps, `@wokwi/elements` artwork.

**Spec:** `docs/superpowers/specs/2026-10-04-dht22-design.md`

## Global Constraints

- Pin sizes in millimetres; element `pinInfo` px convert at 25.4/96.
- Temperature knob is the shared `TEMPERATURE_KNOB` (0-100 C); humidity knob is min 0, max 100, step 1, defaultValue 50.
- The single-wire waveform is not modeled in v1; record the limit in code.
- `NC` is a real pin position with no netlist stamp.

## Review Focus

- `dht.temperature` on a pin with no DHT wired returns 0 instead of throwing.
- Humidity knob at its extremes still reads exactly 0 and 100.
- `SDA` idles high through its pull-up with no sketch running.
- A sketch calling `dht.begin` twice on different pins reads each part's own knobs.
- Cloning the part (two DHT22s) gives independent readings per part id.

**Interfaces:**
- Consumes: `dhtDefinition()`, `TEMPERATURE_KNOB`, `HUMIDITY_KNOB` from Task 1; member-call dispatch at `interpreter.ts:574-596`; optional-service pattern (`lcd?`, `servo?`, `pulseInBegin?`); `servoOnPin` lookup at `simulation.ts:721-731`.
- Produces: `DhtPort { begin(pin): void; temperature(pin): number; humidity(pin): number }` (all optional on `FirmwareServices`); interpreter maps `dht.*` and `DHT.*` targets.

Netlist `case 'dht'`: `SDA` gets a 10k pull-up to `VCC` plus an open `NC`-style nothing for `NC` (no stamp at all); `VCC`/`GND` are topology only. Record the v1 waveform limit in a code comment on the case.

Interpreter: add `if (callee.target.name === 'dht' || callee.target.name === 'DHT') return this.evaluateDhtCall(callee.member, args, services);` after the servo branch at `interpreter.ts:582-584`. `evaluateDhtCall` (sync, like `evaluateServoCall`): `begin` returns 0; `temperature`/`humidity` return `services.dht?.temperature(pin) ?? 0` (same for humidity); default returns 0.

Simulation services: `dht: { begin: () => {}, temperature: (pin) => this.dhtOnPin(pin) knob read ?? 0, humidity: same }` where `dhtOnPin` mirrors `servoOnPin` (MCU pin to net to part whose `SDA` pin shares it) but returns the part; knob reads go through `this.controls.knob(part.id, TEMPERATURE_KNOB)` / `HUMIDITY_KNOB`.

- [ ] **Step 1: Write the failing tests**

```ts
import { describe, expect, it } from 'vitest';
import { FirmwareRunner, type FirmwareServices } from './interpreter';

function stubServices(dht?: { temperature: (pin: number) => number; humidity: (pin: number) => number }): FirmwareServices {
  return {
    nowMs: () => 0,
    pinMode: () => {},
    digitalWrite: () => {},
    digitalRead: () => 0,
    analogWrite: () => {},
    analogRead: () => 0,
    serialBegin: () => {},
    serialWrite: () => {},
    wire: { begin: () => {}, beginTransmission: () => {}, write: () => 1, endTransmission: () => 0, requestFrom: () => 0, read: () => -1, available: () => 0 },
    spi: { begin: () => {}, transfer: () => 0, end: () => 0 },
    ...(dht ? { dht: { begin: () => {}, ...dht } } : {}),
  };
}

describe('dht firmware', () => {
  it('reads knob climate through the port', () => {
    const seen: string[] = [];
    const services = stubServices({
      temperature: () => 23.5,
      humidity: () => 61,
    });
    const runner = new FirmwareRunner(
      'void setup() { float t = dht.temperature(2); float h = dht.humidity(2); Serial.println(t); Serial.println(h); } void loop() { delay(1000); }',
      { ...services, serialWrite: (text) => seen.push(text) },
    );
    let guard = 0;
    while (runner.step() !== null && guard++ < 100_000) {}
    // Floats print through formatPrintValue; match loosely, not exactly.
    expect(seen.join('')).toContain('23.5');
    expect(seen.join('')).toContain('61');
  });

  it('reads 0 with no dht service', () => {
    const seen: string[] = [];
    const runner = new FirmwareRunner(
      'void setup() { Serial.println(dht.temperature(2)); } void loop() { delay(1000); }',
      { ...stubServices(), serialWrite: (text) => seen.push(text) },
    );
    let guard = 0;
    while (runner.step() !== null && guard++ < 100_000) {}
    expect(seen.join('')).toContain('0');
  });
});
```

Check `Serial.println(float)` output through `formatPrintValue` in the interpreter; the test matches loosely with `toContain` so float formatting cannot break it. Plus a netlist test in `dht.test.ts`: SDA idles above 2.8V with VCC driven and nothing else on the net (direct terminal wires, no breadboard, per the encoder-test precedent).
