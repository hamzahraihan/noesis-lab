# IR Remote + Dialer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a hold-to-send IR remote that pulls receiver DAT low with its NEC code plus a rotary dialer whose latched digit reads through a new port.

**Architecture:** New `ir-remote` (pinless) and `rotary-dialer` component kinds in focused sim files; engine-owned transmission and dialed-digit maps following the relay `relayEnergized` precedent; new optional `IrPort`/`DialerPort` firmware services; Wokwi artwork wired through `WOKWI_PARTS`.

**Tech Stack:** TypeScript, Vitest, existing solver stamps, `@wokwi/elements` artwork.

**Spec:** `docs/superpowers/specs/2026-10-04-ir-dialer-design.md`

## Global Constraints

- Pin sizes in millimetres; element `pinInfo` px convert at 25.4/96.
- Remote `key` knob indexes 20 NEC codes, min 0, max 20, step 1, default 0.
- Transmission releases 200 ms after release.
- Dialer `digit` knob is min 0, max 9, step 1, default 0; unread dial returns -1.
- Carrier bursts and pulse trains are not modeled in v1; record the limits in code.

## Review Focus

- `ir.readCode` on a pin with no receiver wired returns 0 instead of throwing.
- Two remotes pressed at once transmit one code (lowest part order) rather than corrupting.
- Receiver knob behavior is unchanged when no remote is on the bench.
- `dialer.read` before any dial returns -1, not digit 0.
- Dialing while the digit knob moves mid-hold latches the release-time value consistently (document which: the hold-time value).

Document the mid-hold rule: the code follows the key knob live while held (simplest consistent semantic — the last answer to Review Focus line 5 is "hold-time value wins because the flag is re-armed every solve").

### Task 2: Receiver air-link and `ir` port

**Files:**
- Modify: `src/sim/firmware/interpreter.ts` (`IrPort` + dispatch + handler)
- Modify: `src/sim/netlist.ts` (receiver `DAT` ORs knob with transmission)

- Test: `src/sim/firmware/ir.test.ts` (create); extend receiver coverage in `src/sim/modules.test.ts` or a new `src/ui/ir-simulation.test.ts`

**Interfaces:**
- Consumes: `irCode()` from Task 1; `evaluateDhtCall` shape; `dhtOnPin` lookup shape; receiver `openDrainOutput('DAT', ...)` at its netlist case.
- Produces: `IrPort { readCode(pin): number }` (optional on `FirmwareServices`).

Netlist receiver case: sinking condition becomes `knob >= 0.5 || transmitting` where transmitting comes from an engine-passed flag. Threading decision (smallest change satisfying the spec): the existing `openDrainOutput` helper takes a boolean, so pass `irTransmitting: boolean` as another optional `buildNetlist`/`elementsForPart` param defaulting false — the same shape as `relayEnergized`/`sonarMeasuring`. Engine `rebuild()` and the relay re-solve path pass `this.irTransmitting !== null`.

Interpreter: `if (callee.target.name === 'ir' || callee.target.name === 'IR') return this.evaluateIrCall(...)` after the dht branch. Handler (sync): `readCode` returns `services.ir?.readCode(pin) ?? 0`; default 0. Simulation: `ir: { readCode: (pin) => { const part = this.irReceiverOnPin(pin); return part ? this.engine.irCode() : 0; } }` with `irReceiverOnPin` mirroring `dhtOnPin` on the `DAT` pin of `ir-receiver` parts.

### Task 3: Dialer part and `dialer` port

**Files:**
- Create: `src/sim/dialer.ts`
- Modify: `src/sim/catalog.ts` (add `rotary-dialer` kind)
- Modify: `src/sim/netlist.ts` (join topology-only group)
- Modify: `src/sim/firmware/interpreter.ts` (`DialerPort` + handler)
- Modify: `src/sim/engine.ts` (dialed-digit map + pump)
- Modify: `src/ui/simulation.ts` (`dialer` services + lookup on `DIAL`? No: on the part wired to the pin — see below)
- Modify: `src/ui/wokwi.ts` (`pushWokwiState` sets `digit`)
- Test: `src/sim/dialer.test.ts` (create)

**Interfaces:**
- Consumes: relay-map prune pattern; `evaluateDhtCall` shape.
- Produces: `dialerDefinition()`, `DIGIT_KNOB` (min 0, max 9, step 1, default 0), `DialerPort { read(pin): number }` (optional; -1 before first dial), engine `dialedDigit(partId): number`.

Dialer definition: pins `GND` x 32.29, `DIAL` x 34.83, `PULSE` x 37.36, y 75.67 (bottom-edge row snapped; record in code); width 70.4, height 75.6; `knobs: [DIGIT_KNOB]`; `momentary: true`; `GND` carries `net: 'GND'`. Lookup pin for the port: the `DIAL` pin's net (the line a sketch watches; `PULSE` stays unconnected in v1 sketches). So `dialerOnPin` mirrors `dhtOnPin` on the `DIAL` pin.

Engine: `dialedDigit = Map<partId, number>`; pump after solve: for each dialer part, if `isPressed(part.id)` set to `state.knob(part.id, DIGIT_KNOB)` (hold-time value per the ledger rule); pruned on rebuild. `dialedDigit(partId)` returns map value or -1. Netlist: join the topology-only group (no stamps — `PULSE` unmodeled in v1, recorded in code).

Interpreter: `dialer.*` dispatch after the ir branch; handler: `read` returns `services.dialer?.read(pin) ?? -1`; default -1? No: unknown members return 0 per convention (servo/dht handlers); only the service-absent path returns -1 via the optional chain — implement as `services.dialer ? services.dialer.read(pin) : -1`. Simulation: `dialer: { read: (pin) => { const part = this.dialerOnPin(pin); return part ? this.engine.dialedDigit(part.id) : -1; } }`. `pushWokwiState`: `if (kind === 'rotary-dialer') { set(element, 'digit', String(this-dialed-or-knob)); return; }` — decision: show the latched dialed digit, falling back to the digit knob before the first dial (both read from engine/controls; no new FootprintState plumbing — mirror the slide-switch `value` line which reads `state.controls` directly, using `engine.dialedDigit` via a `simulation` accessor? `pushWokwiState` only receives `FootprintState`. Ruling: show the digit *knob* (operator's setting, always available in state.controls) rather than the latched value — the knob is what the operator turns, and the latched value equals it whenever held. One line, no plumbing.
