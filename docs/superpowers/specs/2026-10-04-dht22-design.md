# DHT22 temperature/humidity sub-project — Design

Date: 2026-10-04. Status: draft, pending user review. First Tier-3
sub-project; NeoPixel family, IR remote + dialer, and MicroSD remain
separate specs.

## 1. Outcome and scope

Adopt the DHT22 (`wokwi-dht22`) with honest-enough simulation: a part
carrying temperature and humidity knobs, readable from sketches through
a new `dht` firmware port. Success is a sketch printing the knob
climate off a wired part. The single-wire waveform is explicitly not
modeled in v1 -- an acknowledged limit, recorded in code -- so
timing-faithful bit-bang sketches are out of scope.

## 2. Part

New `dht` component kind with 4 pins from the element `pinInfo` (x 15 /
24.5 / 34.1 / 43.8 px → ~3.97 / 6.48 / 9.02 / 11.59 mm; y 114.9 px →
~30.39 mm, a bottom-edge row snapped to the grid). Size 15.1x30.885.
`NC` is a real pin position with no netlist stamp, so a jumper clipped
there reads floating like hardware. Controls: the shared
`TEMPERATURE_KNOB` (0-100 C) and a new humidity knob (0-100 %).
Artwork `wokwi-dht22`, stateless: the element exposes no value props,
so `pushWokwiState` sets nothing.

## 3. Firmware API

New optional `DhtPort` on `FirmwareServices`, following `ServoPort`:
`begin(pin)`, `temperature(pin)`, `humidity(pin)`, returning the wired
part's knob values. The interpreter maps `dht.*` member calls beside
the `servo.*` handler. Lookup mirrors `servoOnPin`/`sonarOnPin`: MCU
pin number to net to the part whose `SDA` pin shares it; no part wired
reads 0. `begin` is accepted beyond lookup like `servo.attach`.
Optional on the interface so existing test stubs keep compiling.
Netlist: `SDA` gets a 10k pull-up to `VCC` (idle-high bus) and no
driver in v1.

## 4. Catalogue, UI wiring, tests

Catalogue `dht22-temp-humidity` in the `input` group, strip-placeable.
`WOKWI_PARTS.dht22` at 15.1x30.885 with a `wokwiPartFor` mapping;
`wokwi-library.ts` flips `wokwi-dht22` to `placed`. Selection and
preview follow from `renderedSizeMm`. Tests: definition pins and
knobs; knob values through the interpreter against a stub `dht`
service; an end-to-end `Simulation` sketch reading both channels off a
wired part; unwired pin reads 0; `SDA` idles high; `renderedSizeMm`
and tag locks.
